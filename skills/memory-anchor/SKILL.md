# 记忆锚点治理 SOP（让 AI 不厌食、不随窗口消失）

## 一句话结论
AI 的"记忆"分三层，只有**写进文件的层**才持久、才跨窗口。对话气泡层（窗口级）关掉就没；系统自动生成的 profile 层会被后台重写覆盖；唯一可靠的是**用户级 MEMORY.md + 工作区日志 + 锚点指针目录**这三样磁盘文件。把记忆治理做成固定动作，AI 就不会"换窗口就忘""开着开着就失忆"。

## 核心原则（最重要的一条）
**"读进来的只活一次，写进文件的才是记忆。"**
任何重要结论、约定、规矩、红线，必须落盘到固定路径文件，不能只停在对话气泡里。对话气泡是一次性显示，文件才是永久真相源。

## 三层记忆架构（各自坑位，必读）
1. **用户级 MEMORY.md**（约 4000 字硬上限，系统自动注入到每次对话）
   - 角色：跨项目索引 + 永久红线 + 项目指针。
   - 坑：超上限会被**静默截断**（曾实测砍掉整节，对话里还显示"已截断"但数据在磁盘）。必须守门精简。
2. **工作区日志 `YYYY-MM-DD.md`**（append-only，仅当前项目可见）
   - 角色：当日操作流水、决策理由、踩坑，跨会话可查。
   - 坑：只能记当前项目，跨项目事实要回流到用户级 MEMORY.md。
3. **系统 profile（`memory/<uuid>_memory.md`）**（系统每日凌晨据对话聚合生成）
   - 角色：云端给 AI 的"用户画像"摘要。
   - 坑：**会被后台重写覆盖**——手改可能被下次聚合冲掉；含错误信息（如把日期写错星期）会持续误导后续注入。
   - 原则：**只登记错误、不手改**，除非用户明确授权破例（破例后若复发再修）。

## 锚点指针目录范式（记忆设定.txt 思路）
把"全文副本"改为"只放指针"，避免副本漂移（两个真相源必然漂移）。六个锚点：
- 【1】每天睁眼读的 → MEMORY.md（自动加载，字数上限，守门）
- 【2】人设灵魂 → SOUL.md + IDENTITY.md + USER.md
- 【3】编码工作准则（唯一保留正文的一项：短，且是给 AI 的指令）
- 【4】完整仓库指针 → 对话存档 / 知识库总账 / 环境坑清单 / 技能踩坑 / 项目主页
- 【5】灾备快照 → `archive/记忆快照-YYYY-MM-DD.txt`（每日自动生成，保留最近 30 份，不依赖任何系统的救生艇）
- 【6】对话存档规范（何时存、怎么命名、双格式）

改这份目录的规矩：**只放指针，要写正文去改源文件**。

## 每日守门（自动化，建议每日固定时刻）
- 量 MEMORY.md 字数：超出软上限提醒精简，超硬上限告警并点名"丢了哪几节"
- 导出灾备快照拼接（SOUL+IDENTITY+USER+MEMORY+坑清单）到 `archive/`
- 与 cross-window-handoff 协同：换窗口前先做交接，再守门

## 系统 profile 漂移修正 SOP（破例时才做）
1. 定位错误：`grep -nE "错误关键词" memory/<uuid>_memory.md`（注意同一信息常多处重复）
2. 全量字符串替换（用 Python 按子串替换，绕过行号在 Read 后被后台重写导致的 Edit 不匹配）：
```python
p = "memory/<uuid>_memory.md"
s = open(p, encoding="utf-8").read()
s = s.replace("旧串1", "新串1").replace("旧串2", "新串2")
open(p, "w", encoding="utf-8").write(s)
```
3. 验证：`grep` 确认 0 残留。
4. 注意：改后若系统重新聚合可能复发，源对话已纠正则下次应正常；复发再修。

## 与 cross-window-handoff 的关系
- 本技能管"记忆**怎么不丢**"（三层架构 + 锚点 + 守门 + 快照 + profile 修正）。
- `cross-window-handoff` 管"窗口**怎么交接**"（换窗口时抢救编辑历史、接上上下文、重建显示）。
- 两者配合 = 完整防失忆方案：平时靠本技能不丢，换窗口靠交接不丢。

## 为什么对新手重要（给第一次配 AI 记忆的人）
新手最常踩的坑：把重要约定只说在对话里，结果下次开新窗口 AI 全忘了；或发现 AI 突然"记错"了（其实是系统 profile 聚合出错）。本技能把三件事讲透：① 什么该写文件、什么不用；② 怎么防止被截断；③ 系统自动生成的那层为什么会骗你。照做即可让 AI 长期稳定记得你。

## 占位符说明（部署时替换）
- `{{WORKBUDDY_HOME}}` = WorkBuddy 配置根目录（Windows 通常 `C:/Users/<你的用户名>/.workbuddy`，macOS/Linux 通常 `~/.workbuddy`）
- `{{KB_DIR}}` = 你存放知识库/文档的固定目录（示例：`~/知识库`）
- `{{BACKUP_ROOT}}` = 你的外部备份盘根目录（原示例 `U:/备份`）
- `<uuid>` / `<your-user-id>` = 你本机 WorkBuddy 生成的用户目录标识
